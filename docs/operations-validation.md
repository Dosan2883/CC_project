# 운영 설정과 검증

## 외부 AI 동의 및 전송 범위

사용자는 설정의 **외부 AI 텍스트 전송 허용**에서 계정 동의를 저장하거나 철회한다. 기존 브라우저 동의값은 계정 동의로 이전하지 않는다. 서버는 외부 호출 직전에 계정 동의와 현재 방 멤버 여부를 확인한다. 철회하면 이후 새 외부 호출과 원문 변경에 따른 자동 재생성이 차단된다. 이미 전송된 요청은 취소할 수 없으며 원본 및 저장 결과는 기존 방 접근 정책을 따른다.

OCR과 STT는 미디어 워커에서 실행한다. 번역·요약·일정 찾기에는 저장된 선택 텍스트만 사용한다. 비공개 방의 새 외부 AI 호출은 기본적으로 차단한다. 배포 책임자가 공급자의 처리 목적, 보존 기간 및 삭제 조건을 확인해 문서화한 경우에만 웹과 AI 워커 양쪽에 `AIAllowPrivateRooms=1`을 설정한다. 애플리케이션은 공급자의 보존 기간을 설정하거나 이미 전송된 텍스트를 회수하지 않는다.

웹과 AI 워커는 공유 DB에서 UTC 일별 외부 호출 수를 선점한다. `AIDailyCallLimit` 기본값은 500이며 0을 지정하면 새 호출을 차단한다. 캐시 적중은 집계에서 제외하고, 송신을 예약한 요청은 시간 초과 또는 실패 때도 해당 일에 집계한다. 각 배포의 두 스택에 동일한 값을 설정한다. 금액 기준의 AWS 예산과 서비스별 요금은 호출 개수 제한과 별도로 운영자가 설정하고 확인한다.

## CloudWatch

1. EC2 인스턴스 프로파일과 AI 워커 Lambda 역할에 지정한 네임스페이스에 대한 `cloudwatch:PutMetricData` 권한을 부여한다. 스택을 배포하는 역할에는 대시보드 생성·변경 권한이 필요하다.
2. 두 스택에 `EnableMonitoring=1`과 동일한 `MetricsNamespace`를 지정한다. 여러 스택이 같은 리전에 있으면 별도의 네임스페이스를 사용한다. `learner-lab.yaml`에는 기존 미디어 DLQ의 이름과 AI 스택 출력의 `AIDLQName`을 전달한다.
3. 테스트 방에서 WebSocket 연결을 열고 메시지, 미디어 처리, AI 작업을 실행한다. `<스택 이름>-messenger` 대시보드에서 ALB 정상 대상, 연결 수, 메시지 수신 서버까지의 P95 지연, EC2 CPU 및 메모리, DB 대기 작업, 언어별 OCR·STT 처리 시간, AI 실패율·429율, DLQ 및 재시도율을 확인한다.

메시지 지연은 서버 저장 시간부터 서버의 WebSocket 전송까지 측정한다. 브라우저 렌더링은 포함되지 않는다. DB 기록의 최종 실패 수와 SQS DLQ 대기 건수는 다른 지표다. 지표의 차원에는 방·계정 식별자나 텍스트가 들어가지 않는다.

## 언어 품질 샘플

아래 문장을 테스트 방에서 사용한다. 각 언어에 대해 샘플 문장을 이미지나 PDF로 만들고, 동의한 화자가 문장을 읽어 WAV 또는 MP4를 만든다. 문장의 날짜와 회의실을 요약 평가의 필수 사실로 사용한다.

| 언어 | 원문 |
| --- | --- |
| 한국어 | 다음 검토 회의는 5월 12일에 B2 회의실에서 열립니다. |
| 영어 | The next review meeting will take place on May 12 in room B2. |
| 일본어 | 次回のレビュー会議は5月12日にB2会議室で行います。 |
| 중국어 간체 | 下次评审会议将于5月12日在B2会议室举行。 |
| 스페인어 | La próxima reunión de revisión será el 12 de mayo en la sala B2. |
| 프랑스어 | La prochaine réunion de révision aura lieu le 12 mai dans la salle B2. |

1. 원본과 실제 처리 결과를 JSONL에 입력한다. OCR·STT는 원문과 추출문, 번역은 평가자 점수 `humanScore`(1~5), 요약은 필수 사실 목록 `requiredDecisions`를 기록한다. 처리 시간은 `durationSeconds`를 쓰고, 검토·수정 건수를 셌다면 `reviewedUnits`와 `correctedUnits`를 넣는다.
2. 자막은 `kind: "subtitle"`로 저장한다. `reference`와 `actual`에는 동일 발화 단위를 동일한 `id`로 정렬한 `[{ "id": 1, "start": 0.5, "end": 1.8 }]` 목록을 넣는다. 브라우저에서도 청크 경계와 이동 후 동기를 확인한다.
3. `python -m scripts.evaluate_languages samples.jsonl --output quality-results.json`을 실행한다. 누락 언어·항목, CER·WER, 수정 비율, 처리 시간, 번역 점수, 요약 누락 사실, 자막 시각 오차를 점검한다. 품질 보고서에 모델 버전, 실행 환경, 실제 결과 JSON과 수동 평가 근거를 첨부한다.

## 장애 시연

실습 전용 스택과 합성 자료에서 진행한다. 이미 연결된 WebSocket 클라이언트 두 개로 메시지 순번과 미디어 작업 ID를 기록한다. 작업이 처리 중일 때 테스트 워커를 중단하고 대체 워커가 같은 작업 ID를 완료하는지 확인한다. 이어 채팅 인스턴스 한 대를 교체하고, 중단 전후 메시지를 재접속해 순번 누락이나 중복 표시가 있는지 확인한다. 시작·중단·복구 시각, 최종 작업 상태, CloudWatch 화면을 시연 영상과 결과표에 기록한다.
