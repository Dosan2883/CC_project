# 2026-11-12 목록·입장 및 전체 점검 후 수정

1. 생성·참가 API가 성공하면 응답 방을 즉시 목록에 넣고 입장한다. 내 방/공개방 GET은 독립적으로 갱신하며 한 목록 실패가 다른 목록을 버리지 않는다. 실패 시 다시 불러오기 버튼을 표시한다.
2. 공통 API 요청에 취소와 제한 시간을 추가했다. 기본 10초, 여러 문서 조각을 처리하는 동기 번역은 120초다. 목록 폴링은 진행 중 요청을 공유하고 로그아웃·새 세션·목록 재시도 시 이전 요청을 취소한다. 토큰·목록 세대가 다른 응답은 반영하지 않는다. 이전 계정의 401도 현재 계정을 로그아웃시키지 않는다.
3. 방 목록 조립 중 상세 조회가 404인 방만 건너뛴다. DB 장애와 다른 HTTP 오류는 그대로 전달한다.
4. Redis presence 발행이 실패해도 로컬 presence 전달과 WebSocket 수신 루프는 유지한다. 기존 heartbeat가 Redis 복구 후 접속 현황을 다시 동기화한다.
5. 나가기 성공 시 화면을 닫고 목록을 다시 읽는다. 404는 사라진 방으로 안내하고 닫는다. 403·5xx·네트워크 오류는 화면을 유지하며 재시도를 안내한다.
6. 메시지 선택 체크박스를 숨겨지는 meta에서 메시지별 acts로 이동했다. 연속 메시지도 각각 선택할 수 있다.
7. 배포 ZIP에 requirements-ocr.txt와 scripts/prepare_ocr.py를 포함했다. EC2 worker 초기화에서 전용 의존성을 설치하고 6개 언어 모델을 미리 준비한다. 서비스 시작 전 manifest·버전·캐시 확인을 거친다. 모델 초기화 실패 시 서비스가 준비된 것으로 처리하지 않는다. 모델 캐시는 messenger 계정의 /var/lib/messenger 아래에 둔다.
8. 동기 메시지·문서 번역에서 캐시 대기 후·외부 호출 후·응답 직전에 멤버 권한과 원문 버전/키를 재확인한다. 문서 조각 사이에도 재검사하며 변경 시 409 또는 권한 오류로 이전 결과를 폐기한다. 이미 외부에 전송된 요청 자체를 되돌리는 기능은 아니다.

검사 결과: Python 전체 65개 통과. 기존 프런트엔드 DOM 검사와 새 tests/check_rooms.cjs 통과. 새 검사는 목록 부분 실패·무응답·계정 전환·요청 순서 역전·공개/비공개 생성 후 입장·나가기 오류·연속 메시지 선택을 포함한다. Python에는 실제 로컬 HTTP/WebSocket 연결에서 Redis presence 실패를 주입하는 검사도 추가했다. CloudFormation YAML·Python/JS 문법과 배포 ZIP 구성도 확인했다.

실제 브라우저 렌더링·모바일 클릭, 실제 Redis 서버 중단, EC2 신규 배포와 PaddleOCR 샘플 인식은 실행하지 않았다. 전체 카탈로그를 읽는 목록 조회 비용은 별도 부하 측정 및 인덱스 개선 과제로 남는다. 점검 시 만든 tmp/review_* 스크립트는 수정 전 결함을 재현하는 역사 자료이며 정상 회귀 검사는 tests/를 사용한다.
